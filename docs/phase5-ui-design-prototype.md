# DevPilot Phase 5 对话工作台设计原型

> 可直接交给 Figma AI、MasterGo AI、即时设计 AI、v0、Lovable 或其他前端原型工具。
>
> 设计范围：新任务页、任务详情、历史侧栏、运行概览、对话输入、执行证据、审批、人工介入、恢复、ChangeRequest 和明暗主题。

## 1. 产品定位

DevPilot 是面向开发工程师与 Tech Lead 的工程 Agent。用户通过自然语言描述代码任务，系统在隔离工作区中完成计划、诊断、修改、风险判断和验证。

界面采用熟悉的 Agent 对话结构，但必须保留工程系统的安全边界：

- 普通消息只补充上下文，不修改 Plan，也不能隐式批准、拒绝、取消或恢复任务。
- 正式需求变更必须通过独立的“作为变更需求”入口进入 ChangeRequest 与 ReplanRequest 审计链。
- Plan、Diff、验证报告、预算和事件 Timeline 都是可展开的执行证据，不展示隐藏思维链。
- 高风险 Patch 只能通过绑定具体 Approval、Patch hash、基础版本和 Revision 的操作区批准。
- 历史与关键指标放在左侧，默认不占据主对话区域。

### 设计关键词

```text
Developer Workbench
Conversation-first / Auditable / Calm / Precise / Dual theme
```

## 2. 整体信息架构

全局由三层组成：

1. 顶部栏：品牌、运行时状态、白天/夜间切换、访问凭证。
2. 左侧栏：新建任务、历史搜索、任务列表、可展开运行概览。
3. 主工作区：任务对话与执行证据，底部固定输入区。

路由保持简洁：

| 页面 | 路由 | 目标 |
|---|---|---|
| 新任务 | `/` | 选择仓库并用自然语言发起任务 |
| 任务详情 | `/tasks/{task_id}` | 继续对话并查看完整执行证据 |

│                      │  请修复登录超时后的重复提交问题。                   │

│ │ 补充缓存回归测试  │ │                                                     │

推荐尺寸：

- Top Bar：64 px。
- 左侧栏：288 px；1440 px 以上可增至 320 px。
- 主对话内容最大宽度：1088 px。
- 对话正文最大行长：65 ch。
- 输入区始终位于主区域底部，只有中间对话区域滚动。

## 4. 顶部栏

左侧品牌：

- 36 × 36 px 的 `DP` 字标，深色实底，不发光。
- `DevPilot` 使用 Space Grotesk 700。
- 副标题 `ENGINEERING AGENT` 使用 JetBrains Mono 10 px。

右侧工具：

- 绿色小圆点 + `本地运行时`，同时使用文字表达状态。
- 明暗主题按钮：图标 + 当前模式文字，位于访问凭证左侧。
- `访问凭证` 是安静的文字按钮；展开后显示有标签的密码输入框和保存按钮。
- Theme 与 Token 设置只保存在浏览器本地，不进入 URL。

主题切换应是 120–220 ms 的表面颜色过渡；键盘焦点环立即出现，不参与动画。

## 5. 左侧任务区

侧栏是历史导航，不是第二个 Dashboard。

### 固定内容

- 标题 `任务历史` 和真实任务数量。
- `新建任务` 主按钮。
- 搜索框，支持需求文本和任务 ID。
- 最近任务列表：需求摘要、更新时间、文字状态 Badge。
- 当前任务使用浅色选中底和细边框，不能只靠蓝色区分。

### 运行概览 Disclosure

指标默认收起，点击 `运行概览` 后显示：

- 任务总数
- 进行中
- 需要处理
- 已完成
- Token 消耗（汇总 Prompt 与 Completion 的真实用量）

只展示接口返回后计算的真实数值。不得填充虚构成功率、成本或节省时间。

### 底部状态

单行显示：`事件持久化 · 控制命令显式执行`。这是运行与安全说明，不设计传统多列页脚。

## 6. 新任务页

主区域不是营销 Hero，而是一条 Agent 欢迎消息：

- 标题：`想让这个仓库发生什么变化？`
- 说明：先生成可审计计划，再执行诊断、代码修改和确定性验证。
- 三条短说明：计划版本链、高风险审批、失败恢复点。

底部新任务输入区包含：

1. 仓库路径，可见标签，必填。
2. `运行选项` Disclosure：Git revision 和可选模型。
3. 任务需求多行输入，必填且至少 5 个字符。
4. 辅助说明：任务在独立 worktree 中运行。
5. 主操作：`创建并开始规划`。

创建失败时，错误信息必须说明未创建，并提示核对仓库路径或服务连接。

## 7. 任务详情对话

### 紧凑 Header

- 状态 Badge + Revision。
- 任务需求作为页面 H1；长文本允许换行且不溢出。
- 下方显示紧凑 task ID 和 run ID。
- 右侧只保留上下文相关操作，如 `恢复`、`取消任务`。

### 消息类型

用户消息：

- 右侧对齐，使用低饱和浅蓝表面。
- 最大宽度 88%，圆角不做夸张气泡尾巴。

Agent 消息：

- 左侧 32 px `DP` 字标。
- 标题行包含 `DevPilot` 与时间/阶段。
- 正文只展示可审计摘要。

系统消息：

- 使用细竖规则和普通文本，不使用高饱和通知卡。

### 当前状态摘要

首条 Agent 状态消息包含四项紧凑数据：

- 实际任务模型
- 当前 Plan 版本
- 暂停原因
- Event Stream 连接状态

数字、Revision、模型和 ID 使用 JetBrains Mono，并开启 tabular numbers。

## 8. 执行证据

执行证据位于对话后方，用一条清晰分隔线进入；不是另一个页面，也不做卡片套卡片。

标签：

1. 执行概览
2. 事件时间线 + 真实事件数量
3. 代码变更
4. 验证报告

标签只用文字和底部 cobalt 细线表达当前项。移动端允许横向滚动，标签文字不得换行。

### 执行概览

- 主列：Plan、Verification。
- 辅列：Budget、最近 6 条 Timeline。
- 960 px 以下合并为单列。

### Timeline

- 倒序展示 sequence、node、event type、时间、revision/checkpoint 状态。
- `checkpoint 已确认`、`等待 checkpoint`、`独立事件`必须以文字区分。
- WebSocket 断线时显示 `正在恢复` 或 `游标补拉`，不清空已有事件。

### Diff

- 文件标签横向滚动。
- 代码区是深色阅读表面，即使在 Light Mode 也保持稳定代码对比。
- 行号固定视觉宽度；Added、Removed、Hunk 使用不同文字与背景组合。
- 不绘制假的浏览器、IDE 或代码窗口标题栏。

### Verification

- PASS/FAIL 使用文字 + 色彩。
- 展示 summary、exit code、failed test count、command。
- 没有数据时明确写 `尚未执行验证`，不得编造结果。

## 9. 底部消息输入

标签：`给任务发消息`。

输入区上方或右侧持续显示：`普通消息不会修改 Plan`。

操作：

- 次要按钮 `作为变更需求`：打开正式 ChangeRequest。
- 辅助提示 `Ctrl + Enter 发送`。
- 主按钮 `发送消息`。

发送成功后消息直接进入对话，不显示多余“发送成功”Toast。网络失败时保留草稿，并给出重试指导。

## 10. 高风险控制

### Approval

- 标题：`高风险变更等待审批`。
- 展示 Approval ID、Patch hash、base revision、过期时间。
- 必须勾选 `我已核对当前 Patch 与风险信息` 后才能批准。
- 主危险动作使用琥珀色，拒绝使用红色边界；状态变化冲突后刷新并要求重新核对。

### Intervention

- 标题：`自动执行已安全停止`。
- 展示错误类别、错误码、摘要和建议动作。
- 操作：`提交修正要求`、`查看恢复点`。

### ChangeRequest

- 明确写出它会进入 ReplanRequest 审计链。
- 如果当前 Patch 等待审批，必须提示将废弃当前 Approval 与 Patch。
- 二次确认后才能提交。

### Recovery

- 展示 Plan 版本、创建时间和仓库快照。
- 明确区分当前 Run 内回滚和创建新 Run 的完整恢复。
- 必须确认下游 Patch 和验证结果会失效。

## 11. 双主题视觉 Token

全部颜色使用 OKLCH，并围绕 255° cobalt 锚点构建。不得出现纯黑、纯白、紫蓝渐变、玻璃拟态或发光阴影。

### Light Mode（默认视觉方向）

- 页面：冷调近白纸面，约 L 98%。
- 侧栏：略深的冷调纸面，约 L 96%。
- 主文字：深海军蓝，约 L 20%。
- 边框：蓝灰色，约 L 86%。
- Cobalt：约 L 54%、C 0.16，只用于焦点、当前项、链接和小型信号。

### Dark Mode

- 页面：低眩光深蓝，约 L 15%。
- 面板：L 19%–22%，较高表面更亮。
- 主文字：冷调近白，约 L 94%。
- Cobalt：L 70%、C 0.13，保持同一色相但降低色度。
- 不使用深色卡片外发光。

### 状态色

- Positive：绿色 + 明确文字。
- Warning：琥珀 + 明确文字。
- Danger：红色 + 明确文字。
- Running：偏青蓝 + `执行中` 文字。

## 12. 字体与间距

字体全部随前端包本地构建：

- Display：Space Grotesk 500 / 700。
- Body：IBM Plex Sans 400 / 500 / 600；中文回退到 Segoe UI 或系统中文字体。
- Mono：JetBrains Mono 400 / 600。

4 pt 间距系统：2、4、8、12、16、24、40、64、96 px。

- 所有可触控控件至少 44 × 44 px；粗指针环境提升到 48 px。
- Input 与相邻 Button 高度一致。
- 面板圆角约 14 px；输入和按钮约 10 px。
- 输入边框在默认、Hover、Focus、Error 状态保持相同宽度。

## 13. 响应式

必须验证 320、375、414、768、960 和 1440 px。

### 小于 960 px

- 左侧栏变为离屏 Sheet。
- 主 Header 左上显示 `任务历史` 按钮。
- 打开侧栏后出现可点击遮罩，并提供关闭按钮。
- 主区域保持对话与底部输入结构。

### 小于 640 px

- 隐藏顶部运行时文字，只保留主题和凭证操作。
- 主题按钮可只显示图标，但保留 aria-label。
- Header 操作按优先级收缩。
- 当前状态四列变为两列。
- Composer 操作自动换行，按钮文字保持单行。
- 弹窗操作可换行，但每个按钮至少 44 px 高。

所有宽度：

- `html` 与 `body` 使用 `overflow-x: clip`。
- 页面不使用 `100vw`。
- 长标题使用 `overflow-wrap: anywhere`。
- Diff、Tabs 与 Timeline 在自身区域内滚动。

## 14. 动效与状态

最多使用三类动效：

1. 明暗主题表面颜色切换，220 ms。
2. 移动侧栏进入/退出，420 ms exponential ease-out。
3. 按钮按压 1–2 px，120 ms。

禁止：

- 全页面滚动淡入。
- Bounce、Elastic、发光 Hover。
- `transition: all`。
- 无限装饰动画。
- Focus ring 淡入。

开启 `prefers-reduced-motion: reduce` 时，取消空间位移，过渡不超过 150 ms；功能型 Loading 仍保留。

## 15. 可访问性验收

- 正文对比度至少 4.5:1，重要控件边界至少 3:1。
- 所有输入都有可见 Label，Placeholder 仅提供示例格式。
- 所有交互控件支持键盘并具有立即出现的 Focus ring。
- 状态、错误和验证结果不只依赖颜色。
- Modal 可通过 Escape、遮罩和关闭按钮退出，并正确管理焦点。
- WebSocket/加载状态使用 `aria-live="polite"`，不逐事件打断读屏。
- 按钮、导航、标签文字在 320–1920 px 内保持单行。

## 16. 可直接粘贴给设计工具的 Prompt

```text
请设计一个名为 DevPilot 的工程 Agent Web 工作台，Desktop 1440×900，并补充 375×812 移动版。

顶部 64px：左侧 DP 字标 + DevPilot + ENGINEERING AGENT；右侧依次为本地运行时、白天/夜间切换、访问凭证。

左侧 288px：任务历史标题、新建任务按钮、搜索框、默认收起的运行概览、最近任务列表、底部“事件持久化 · 控制命令显式执行”。运行概览展开后显示真实任务总数、进行中、需要处理、已完成。

```
